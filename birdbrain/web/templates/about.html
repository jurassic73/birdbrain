{# ---------- 3. Detection rules ---------- #}

When movement counts as a visit

Rim and rocks

Each small-stream frame is compared with a slowly updating picture of the empty bath. A visit starts when at least {{ pct(cfg.MOTION_MIN_AREA) }}% of the watched area changes for {{ cfg.TRIGGER_FRAMES }} frames in a row (the dashed line). One flicker is not enough.

{% if cfg.WATER_WATCH and zones.water %}

Open water

Water sets off simple motion detectors constantly, so the open water has its own rule. It needs exactly one strong, compact blob between {{ pct(cfg.WATER_MIN_BLOB) }}% and {{ pct(cfg.WATER_MAX_BLOB) }}% of the water's area, staying near the same spot for {{ cfg.WATER_PERSIST_FRAMES }} frames in a row. Raindrop rings fade faster than that. It rests at night, when nothing flies in to land on the water. {% if presence_mode != 'off' %}Even then, the Pi's animal check looks first, so a drifting leaf never costs a Claude call.{% endif %}

{% endif %} {% if zones.ground %}

Ground around the bath

The lawn moves all day, so the ground has its own rule. It needs one animal-sized blob that stays in view for {{ cfg.GROUND_PERSIST_FRAMES }} frames in a row and moves at walking pace. By day a ground bird is big enough ({{ pct(cfg.GROUND_MIN_BLOB) }}% of the frame); at night it must be about cat-sized ({{ pct(cfg.GROUND_MIN_BLOB_NIGHT) }}%). {% if presence_mode == 'gate' %}The Pi's animal check looks first, and only photos with something in them go to Claude.{% else %}The photo goes to Claude.{% endif %}

{% endif %}

Cooldowns and rainy days

{% if cfg.STAY %}

One visit per stay. While a visitor is still in view, it's the same visit, so a bird that bathes for five minutes is one visit, and its card says how long it stayed (details).

{% endif %}

After a real visitor the camera also rests at least {{ cfg.COOLDOWN_VISIT }} s, so one splashing bird is one visit, not fifty. After a false alarm it waits {{ cfg.COOLDOWN_NONE }} s, and every false alarm in a row doubles the wait, up to {{ cfg.COOLDOWN_NONE_MAX }} s. A real visitor resets it.

{# ---------- 6. Claude ---------- #}

Asking Claude, and asking again when unsure

  1. Haiku looks at the sharpest photo{{ ', cropped' if zones.crop }}
  2. Saw an animal? No False triggers, hidden from the gallery
  3. Sure of every animal? Yes Gallery and alerts. Also when fairly sure of a species already confirmed here {{ confirmed_min }}+ times (the Confirmed pill on Species), as long as the Pi's own classifier, looking at Claude's circle by day, names the same species
  4. Sonnet looks at the 3 sharpest photos together, combining angles
  5. Still unsure? No Gallery and alerts
  6. Review queue: you have the final say

What Claude is told

  1. Instructions: the animal types, how to name species, how sure to be, that night photos are infrared
  2. Your yard from Claude's Notes: what the camera sees, what to look for, what to ignore{% if site.location %}, in {{ site.location }}{% elif not site.scene_notes %} (not filled in yet){% endif %}
  3. Lessons from your corrections: {{ lessons or 'none yet' }}{{ ' in use' if lessons }}
  4. The photo (or photos) and the date and time, so it knows what's in season

It must answer in a fixed format. When more than one kind of animal is in the photo, the most prominent is the main answer and each other kind goes under "also":

{"visitor": "bird",
 "species": "Dark-eyed Junco",

   "species": "Bushtit", "count": 3,

Each of those counts as a visit of its own species on the species pages, stats and first-seen dates, and a first sighting among them still sends the new-species alert.

Learning from your corrections

  1. Claude answers"Dark-eyed Junco, bathing"
  2. You correct it"No animal: those are the rock tips after a refill"
  3. It becomes a lessonThe latest 15 corrections join every prompt
  4. Next photoClaude gets it right, starting with the very next visit

Claude doesn't get retrained; it simply reads your latest corrections every time. The Pi's animal check does retrain on them, in the background within about a minute. You can circle things on the photo, fix the other animals in the shot, or press Ask to have Claude suggest a name (more). {% if totals.corrected %}You've corrected or annotated {{ totals.corrected }} visit{{ 's' if totals.corrected != 1 }} so far.{% endif %}

Missed something? Circle it and ask, cheapest first

  1. You circle itUsually on a false trigger, around the animal it missed, on whichever burst frame shows it best
  2. The Pi looksIts own species model on just the circle: free
  3. Haiku, then SonnetOnly if the Pi isn't sure: a fraction of a cent, then about half a cent
  4. You save itNothing changes until you do

Each answer comes with a Use button that fills in the correction form, and every check is listed on the visit under "How it was decided"{% if totals.owner_checks %} ({{ totals.owner_checks }} Claude check{{ 's' if totals.owner_checks != 1 }} so far, counted in the spend above){% endif %}. How it teaches the Pi

On any photo card, and on the big latest-visitor photo on the home page, the owner can tap the star to cycle it: one tap makes it blue, a favorite; a second makes it yellow, the species cover (the photo shown for that species on the Species page, one per species); a third unsets it. Yellow waits two seconds before it's saved, so tapping straight through to unset leaves the cover alone. If the species already has a cover, it then asks first, showing the current cover and the new pick side by side, each cropped around the animal; Keep current puts the star back to blue. Yellow and blue photos are never deleted when space is cleared (they also get the blue favorite mark). A new cover leaves the old one blue. A pill beside the star says which one it just became.

{# ---------- 10. Under the hood ---------- #}

Under the hood

  • Camera Any camera with two RTSP streams; this project uses an inexpensive Wi-Fi camera with open-source firmware. Its picture and day/night settings can be changed from Settings > Camera, through the camera's own web API; every change is logged and can be undone.
  • Computer A Raspberry Pi on the home network runs the watcher, the local model, the database and this site.
  • Software Python with OpenCV for motion, ONNX Runtime for the local models, FastAPI and htmx for the pages, SQLite for the visits, Chart.js and Leaflet for charts and maps.
  • Privacy Photos and records stay on the Pi. Only the photos Claude is asked about leave the house (plus alert photos to ntfy, and species names to the info sources). A public copy, if set up, never gets a photo where the Pi's person check fires, unless you've looked, seen no one and pressed Public anyway on that visit.
  • Storage Every visit is kept; older photos may be thinned to fit the budget. See Storage.
